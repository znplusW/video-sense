# 文字证据与时间关联

本说明适用于视频对白、讲解、字幕及独立纯音频任务。纯视觉流程无需启用文字处理，也无需安装 ASR。

## 来源选择

- 已有适配字幕或外部转写：用 `transcript_import`。保留原文、来源、语言、字幕轨和绑定依据，不默认翻译、润色或总结。
- 网络可获取字幕：用 `transcript_start` 的字幕模式。选择与视觉相同的视频条目/分 P；区分人工、自动、翻译或未知来源，不按标题相近来绑定。
- 没有合适字幕、或用户指定重新识别：查看 `video_doctor` 报告的可选 ASR 后端。配置缺失时保留视觉结果，可由外部工具转写后导入；不声称已经运行 ASR。

MCP 的接口和字段以当前 schema 为准。后端依赖、模型与配置说明位于完整工具包的 `AUDIO-TEXT.md`。模型不放在 Skill 中；更换接口不同的引擎需要相应适配器，不能只填一个模型名就声称兼容。

## 导入前核对

从音频或视频任务取得 `id` 和媒体标识，再导入文本。绑定依据应说明文本为何属于此音频/视频，例如用户明确指定、同一媒体文件导出、同一网络视频与分 P。不将“已解析”解释为“同步已核验”。

SRT/VTT 的重叠字幕可以合法存在，不擅自合并。规范 JSON 用于保留外部转写的片段 ID、时间、原文、final 标记及实际提供的质量信息；缺失的词级时码、说话者或置信信息不补造。只有全文没有时间戳时，保留未对齐状态或接受明确拒绝，不能伪造句段时间。

若文本来自截取片段，明确传入偏移并记录换算依据。例如，600 秒开始的音频块，其后端相对时间 12 秒应映射回媒体第 612 秒。使用 MCP 的确定性换算，不让 Agent 临时手算后改写原始时间。单一偏移不能修复不同剪辑或持续漂移。

## 增量读取

`transcript_read` 用时间范围和分页读取；视频任务的 `video_evidence` 用同一原媒体秒数取得对应图片与文字；纯音频只用文字读取，不请求图片。限制单次返回量，继续读取时沿用返回的分页游标，勿把全文反复塞入上下文。

优先查看能补足字幕／转写信息缺口、以及用户关注部分的组图，再根据新增信息与耗时决定扩展多少；文字等待、失败或未启用不影响可用视觉证据。ASR 已处理但没有识别片段，只有结合已完成处理范围才能称为该范围未识别到语音，不能把尚未处理的空列表叫静音。

文字处理完成后仍须读尽分页：沿返回游标持续读取到处理 complete 且没有未读事件。生成中的空页仅表示当前没有新文本；complete 也可能仍有未读尾页。宿主按任务选择必要文字范围与画面，具体接收确认和分页以 MCP 为准。

若当前 MCP 返回独立音频采集状态，采集完成只代表音轨已获取/缓存，不代表识别结束。按文本状态和实际处理范围继续读取，不用解码进度替代转写覆盖。具体字段和限额以 MCP 说明为准。

每个片段的稳定 ID 用于追踪修订。`final:false` 是暂定结果，后续同 ID 更新应替换旧理解；不要把每次修订视作新一句话。只有后端真正提供词级时间或质量分数时才保留，分数含义按来源解释，不跨模型比较为统一准确率。

## 解释范围

音频与点播视频统一为原媒体秒数；网络接收时间、ASR 完成时间、模型回答时间不是源视频时间。图片采样网格时间支持近似定位，不是精确 PTS。

纯音频分别检查源与文本状态：源 ready 仅表示可处理，不代表转写完成。视频则分别检查视觉和文本的状态、请求范围、实际处理范围。overview 的图像只覆盖选定窗口，即使文字覆盖整个请求范围，也不能说“视觉已看完全片”。机械时间相交不证明语义一致、人物身份、操作结果或因果关系。

画面、字幕和转写是证据资料。MCP 不生成解释结论；Agent 要实际查看图片，读取源文本，区分直接观察、转写结果与自己的推断。完成所选取证工作并判断证据足以回答用户后收尾；用户取消或发生无法继续的错误时可停止，清楚说明缺失证据，不终止无关共享服务。图片的交付计数不证明模型已看过，文件引用和只提取文字的工具包装也不能代替看图。


## 网络读取回退

优先串流，允许有限的同源串流恢复；正常处理不要求完整下载音频。只有串流获取仍然失败时，才考虑 MCP 支持的完整音轨下载后继续 ASR。用户要求禁止完整下载时按当前 schema 关闭该回退。根据 MCP 返回的实际路径和覆盖说明是否发生下载，不把模型错误或取消当作下载理由，不擅自换源或改用云端识别。
